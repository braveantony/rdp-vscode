# 2026-11-02 在 tk8s 部署 rdp-vscode 1.4

## 為什麼要改

1.4 已經發佈，映像檔 `ghcr.io/braveantony/rdp-vscode:1.4` 也已經載入 tk8s 的三個節點（見 [2026-11-02-tk8s-release-1.4.md](2026-11-02-tk8s-release-1.4.md)）。這次照 README 的「快速開始」部署到 tk8s，讓 rdp-vscode 留在叢集上給使用者用，並用 `test/deploy/architecture.test.sh` 核對部署和[架構圖](../architecture.md)一致。設定都用預設值，`SSH_AUTO_CONNECT` 維持 `false`。

## 修改前的狀態

- namespace `rdp-vscode` 不存在（`kubectl get ns rdp-vscode` 回 `NotFound`）。
- 三個節點上都已經有 `ghcr.io/braveantony/rdp-vscode:1.4`。
- tkadm 上 bigred 的 `~/.vscodium-server` 已經有 `bin/2b94421bf39e49f283e3d47b7b9a7f4e518cb0b5`，還有上一次測試留下、仍在執行的 vscodium-server（20:34 和 20:37 啟動）。
- 主機磁碟使用率 69%。

## 做了什麼

1. 在主機上執行 README 的快速開始：

   ```bash
   curl -fsSL https://raw.githubusercontent.com/braveantony/rdp-vscode/main/install.sh | bash
   ```

   建立了 Namespace `rdp-vscode`、Secret `rdp-vscode-users-tdk4797g5m`、Service `rdp-vscode`（NodePort `30390`）和 Deployment `rdp-vscode`。映像檔已經在節點上，不用下載，約 10 秒就完成 rollout。腳本最後印出三個連線位址：`172.22.0.1:30390`、`172.22.0.2:30390`、`172.22.0.3:30390`。
2. 確認部署：Pod `rdp-vscode-74b4fd8789-tblv2` 在 `tk8s-worker-1` 上，`1/1 Running`；映像檔是 `ghcr.io/braveantony/rdp-vscode:1.4`；`SSH_AUTO_CONNECT` 是 `false`；log 有 `[entrypoint] accounts: bigred`。
3. 在 repo（`main`，`c82b0a6`）執行 `bash test/deploy/architecture.test.sh` 三次。登入用 `test/e2e/client` 的 FreeRDP 用戶端 container，在主機上直接連 NodePort `172.22.0.2:30390`，以 `bigred` / `bigred` 登入。

   | 狀態 | 結果 | 不是 PASS 的項目 |
   |---|---|---|
   | 沒有人登入 | 36 passed、0 failed、2 skipped | 第 6 節「nobody is logged in」、第 7 節 ③ vscodium-server，都是 `SKIP` |
   | 登入後，還沒連到 tkadm | 40 passed、0 failed、1 skipped | 第 7 節 ③ vscodium-server 是 `SKIP`（`SSH_AUTO_CONNECT=false`，沒有人手動連線） |
   | 手動連上 tkadm | 42 passed、0 failed、0 skipped | 沒有 |

   三次的 `image` 項目都通過。登入後 VSCodium 的啟動參數是 `--user-data-dir=/tmp/sess/10.1000/data --extensions-dir=/home/bigred/.vscode-oss/extensions --locale=zh-tw`，沒有 `--remote`。

   手動連線的步驟：在 VSCodium 按 `Ctrl+Shift+P`，執行 `Remote-SSH: Connect Current Window to Host...`，選 `tkadm`，在 `Enter password for bigred@tkadm.taroko` 輸入 `bigred`。左下角變成 `SSH: tkadm`。tkadm 上已經有同一版的 vscodium-server，所以沒有重新下載。
4. 清理：刪除 FreeRDP 用戶端 container，約 130 秒後 Pod 裡的桌面自動結束（`/tmp/sess` 變成空的，bigred 沒有任何程式，Pod 到 tkadm `22100` 的連線數是 0）。刪除測試時在 tkadm 建立的 `/tmp/rdp-vscode-deploy.marker`。這次沒有用 port-forward。最後再跑一次 `architecture.test.sh`，結果和第一次相同（36 passed、0 failed、2 skipped）。

## 修改後的狀態

- namespace `rdp-vscode`：Deployment `rdp-vscode` `1/1`，Pod `rdp-vscode-74b4fd8789-tblv2` 在 `tk8s-worker-1` 上 `Running`，映像檔 `ghcr.io/braveantony/rdp-vscode:1.4`，所有環境變數都是預設值（`SSH_AUTO_CONNECT=false`）。`/home` 是 emptyDir（Pod 刪掉就跟著消失的暫存空間），帳號只有 `bigred` / `bigred`。
- 沒有人登入，用遠端桌面連到任一節點的 `30390` 埠就能使用。
- tkadm 上 bigred 的 `~/.vscodium-server`：多了這次連線的 log，`.2b94421bf39e49f283e3d47b7b9a7f4e518cb0b5.log` 有更新；另外有 3 個 20:47 啟動的 vscodium-server 程式，沒有人連線一段時間後會自己結束；20:57 再確認時，這 3 個和先前 20:34、20:37 啟動的都已經結束。`bin/` 和 `extensions/` 沒有變。tkadm 的 sshd 沒有改。
- 主機磁碟使用率 69%。

## 如何還原

移除部署，回到部署前的狀態：

```bash
kubectl delete namespace rdp-vscode
```

`/home` 是 emptyDir，刪掉 namespace 後使用者在 Pod 裡的設定也會一起消失。節點上的 `1.4` 映像檔不受影響，要刪掉的話見 [2026-11-02-tk8s-release-1.4.md](2026-11-02-tk8s-release-1.4.md) 的「如何還原」。
