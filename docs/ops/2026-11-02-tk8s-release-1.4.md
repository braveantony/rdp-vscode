# 2026-11-02 發佈 1.4：把 `ghcr.io/braveantony/rdp-vscode:1.4` 載入 tk8s 的三個節點

## 為什麼要改

main（`79c494d`）加入了 `SSH_AUTO_CONNECT`（PR #8），`test/e2e/run.sh` 和 [build-image.md](../build-image.md) 的 Step 4 也改用 `skopeo` 載入映像檔（PR #9）。這次照 build-image.md 發佈 1.4，同時第一次實測新的 Step 4：把 `1.4` 載入三個節點，再跑一次完整驗收 `run.sh all`。ghcr.io 上的 `1.3` 不動。寫這份紀錄時 `1.4` 還沒推送，之後同一天推送到 ghcr.io（digest `sha256:aded42671577ec1999b4f653360d0d492d1471154eb9650e2dfc85eca2527ab8`）。

## 修改前的狀態

- namespace `rdp-vscode` 不存在（上一次測試後已刪除，見 [2026-11-02-tk8s-e2e-ssh-auto-connect.md](2026-11-02-tk8s-e2e-ssh-auto-connect.md)）。
- 節點上的 rdp-vscode 映像檔（`sudo podman exec <節點> crictl images | grep rdp-vscode`）：

  | 節點 | 映像檔 |
  |---|---|
  | `tk8s-control-plane-1` | 沒有 |
  | `tk8s-worker-1` | `ghcr.io/braveantony/rdp-vscode:1.1`（`7bba699`）、`localhost/rdp-vscode:dev`（`22ca56f`） |
  | `tk8s-worker-2` | `localhost/rdp-vscode:dev`（`22ca56f`） |

- 主機磁碟使用率 68%。

## 做了什麼

1. 在 `release/1.4` 分支（以 `79c494d` 為基礎）照 Step 2 建置 `ghcr.io/braveantony/rdp-vscode:1.4`，映像檔 ID `22ca56f`。原始碼和上一次建置的 `localhost/rdp-vscode:dev` 相同，所以每一層都用到快取，兩個 tag 指向同一個映像檔。
2. 跑完 Step 3 的所有測試，全部通過。
3. 照 Step 4 的 `skopeo` 迴圈，把 `1.4` 載入 `tk8s-control-plane-1`、`tk8s-worker-1`、`tk8s-worker-2`，三個節點都成功。
4. 執行 `test/e2e/run.sh all`，22 項通過。它重新建置 `localhost/rdp-vscode:dev`（結果還是 `22ca56f`），用 `skopeo` 載入兩台 worker，在 namespace `rdp-vscode` 部署 stateless 和 stateful 測試，也在 namespace `default` 建立 Service `web`。結束時刪除了 namespace `rdp-vscode` 和 `web`。

## 修改後的狀態

- namespace `rdp-vscode` 不存在，`default` 的 `web` 已刪除。
- 節點上的 rdp-vscode 映像檔：

  | 節點 | 映像檔 |
  |---|---|
  | `tk8s-control-plane-1` | `ghcr.io/braveantony/rdp-vscode:1.4`（`22ca56f`） |
  | `tk8s-worker-1` | `ghcr.io/braveantony/rdp-vscode:1.1`（`7bba699`）、`ghcr.io/braveantony/rdp-vscode:1.4`（`22ca56f`）、`localhost/rdp-vscode:dev`（`22ca56f`） |
  | `tk8s-worker-2` | `ghcr.io/braveantony/rdp-vscode:1.4`（`22ca56f`）、`localhost/rdp-vscode:dev`（`22ca56f`） |

  兩台 worker 的 `1.4` 和 `dev` 是同一個映像檔，共用儲存空間；`tk8s-control-plane-1` 多占約 1.3 GB。
- 主機磁碟使用率 69%。
- tkadm 上 bigred 的 `~/.vscodium-server` 有這次連線產生的檔案（目錄修改時間 2026-11-02 20:34）。

## 如何還原

刪掉節點上的 `1.4`：

```bash
for n in tk8s-control-plane-1 tk8s-worker-1 tk8s-worker-2; do sudo podman exec $n crictl rmi ghcr.io/braveantony/rdp-vscode:1.4; done
```

兩台 worker 上的 `1.4` 和 `localhost/rdp-vscode:dev` 是同一個映像檔（ID `22ca56f`）。這個指令沒有實際執行過，執行後請用 `crictl images | grep rdp-vscode` 確認 `dev` 還在。

`localhost/rdp-vscode:dev` 在這次之前就已經在兩台 worker 上，要清掉的話見 [2026-11-02-tk8s-e2e-ssh-auto-connect.md](2026-11-02-tk8s-e2e-ssh-auto-connect.md) 的「如何還原」。這次沒有刪除任何既有的部署，不需要重新部署。
